# v1.2.1 Firestore 기본 카드 배포 전 점검 작업 지시서

작성일: 2026-05-23
작성 주체: 이안(Yian OS)
대상 프로젝트: mabimobi
현재 기준 버전: v1.2.0

## 작업 배경

모비모비를 MacBook Pro / Claude Code 작업 환경에서 Mac mini / Codex 작업 환경으로 이전했어.

이전 후 Firestore 기본 카드 소비 로직까지 연결했고, 로컬 빌드와 기본 라우트 확인은 완료된 상태야.

다만 이번 변경은 기본 카드, 기존 캐릭터 데이터, 체크 상태, 즐겨찾기 보존과 직접 관련이 있기 때문에 실섭 배포 전에 데이터 보존 관점의 점검이 필요해.

## 현재까지 확인된 변경 핵심

- `src/lib/defaultCards.ts` 추가
  - localhost: `draft` -> `published` -> 코드 기본값
  - production: `published` -> 코드 기본값
- `src/hooks/useAppState.ts` 수정
  - 초기 로드
  - 캐릭터 생성
  - 숙제 초기화
  - 기본 프리셋이 Firestore defaults를 사용하도록 변경
- `src/lib/storage.ts` 수정
  - `createHomeworkForChar`
  - `createPurchaseForChar`
  - `createTradeForChar`
  - `createScrollForChar`
  - `loadData`
  - `applyResets`
  - 위 함수들이 주입받은 defaults 기준으로 동작하도록 변경
- 기존 캐릭터의 기본 카드도 Firestore defaults와 동기화되도록 변경
- 기본 카드 수정/삭제/추가가 반영되도록 변경
- 체크/즐겨찾기는 제목 또는 기존 기본 ID 기준으로 최대한 보존하도록 변경

## 이번 작업 목표

- Firestore 기본 카드 로직이 실섭 배포 가능한 상태인지 점검
- 기존 사용자 데이터가 최대한 보존되는지 확인
- 관리자 페이지에서 draft/published 기본 카드 흐름을 확인
- Vercel 환경변수 설정 필요 여부 확인
- 배포 가능 여부를 판단하고, 배포 전 체크 결과를 정리

## 이번 작업에 포함할 것

### 1. 현재 변경 파일 확인

아래 파일을 중심으로 변경 내용을 확인해줘.

```txt
src/lib/defaultCards.ts
src/hooks/useAppState.ts
src/lib/storage.ts
src/types/index.ts
src/app/ctrl-a7x9k2m/
src/lib/adminFirestore.ts
```

특히 아래 관점으로 봐줘.

- production에서 `draft` defaults를 잘못 읽지 않는지
- localhost에서 `draft`가 없을 때 `published`로 fallback되는지
- Firestore defaults가 없을 때 코드 기본값으로 fallback되는지
- defaults 주입 전/후 데이터 구조가 깨지지 않는지
- 기존 캐릭터 데이터가 loadData/applyResets 과정에서 의도치 않게 초기화되지 않는지

### 2. 데이터 보존 시나리오 점검

가능하면 로컬에서 아래 시나리오를 확인해줘.

- 기존 캐릭터가 있는 상태에서 앱 로드
- 기존 체크 상태가 유지되는지 확인
- 기존 즐겨찾기 상태가 유지되는지 확인
- 기본 카드가 추가된 경우 기존 캐릭터에도 반영되는지 확인
- 기본 카드가 수정된 경우 기존 카드와 잘 매칭되는지 확인
- 기본 카드가 삭제된 경우 기존 기본 카드가 의도대로 제거되는지 확인
- 사용자가 직접 만든 커스텀 카드는 삭제되거나 덮어써지지 않는지 확인
- 캐릭터 생성 시 Firestore defaults 기준으로 카드가 생성되는지 확인
- 숙제 초기화 시 Firestore defaults 기준으로 초기화되는지 확인

### 3. 관리자 페이지 점검

관리자 페이지 경로:

```txt
/ctrl-a7x9k2m
```

확인할 것:

- 관리자 페이지 접근 가능 여부
- 기본 카드 draft 저장 가능 여부
- draft -> published 반영 흐름
- published 기본 카드가 앱 초기 로드에 사용되는지
- 관리자 이메일 제한 로직이 현재 의도대로 동작하는지

### 4. Vercel 환경변수 확인

실섭 배포 전에 아래 환경변수가 Vercel에 설정되어야 해.

```txt
NEXT_PUBLIC_ADMIN_EMAIL=inchu594@gmail.com
```

확인할 것:

- 코드에서 해당 환경변수를 실제로 사용하는지
- Vercel에 환경변수가 없을 때 관리자 기능이 어떻게 동작하는지
- 실섭 배포 전 반드시 추가해야 하는지

### 5. 빌드와 기본 라우트 재검증

다시 한 번 아래 검증을 진행해줘.

```txt
npm run build
```

로컬 서버 기준:

```txt
/
/ctrl-a7x9k2m
```

둘 다 정상 응답하는지 확인해줘.
